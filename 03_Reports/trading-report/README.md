## 1. 문서 목적

이 문서는 사용자가 등록된 사용자 정보와 승인 종목, 사용자 프로그램이 수집한 시장 자료를 바탕으로 AI에 결과 생성을 요청하고, 검증된 매매 레포트를 이메일로 받기까지의 실제 개발 경험을 공개 가능한 범위에서 정리합니다.

각 기능은 단순 사용법뿐 아니라 **도입 이유, 사용자와 AI의 역할, 구현 구조, 어려웠던 점, 문제점, 장점과 단점, 개선 결과, 현재 한계**를 함께 설명합니다.

## 2. 전체 처리 흐름

1. 사용자와 결과 수신 이메일 등록
2. 사용자가 매매 대상 종목을 1차 선택
3. AI가 재무·CB/유증·거래정지·상장 위험과 타점 형성 가능성 검토
4. 사용자 승인 후 종목·감시가·매도선 등록
5. 보유종목 등록 및 신규 후보 제외
6. 한국 정규시장과 NXT 마감 후 사용자 키움 OpenAPI 프로그램이 일·월·년 자료 수집
7. 사용자가 수집 원본을 AI에 전달하고 결과 생성 요청
8. AI가 전체 대상과 원본을 전수검사
9. 도달·30% 근접·등급·시총·배당·위험 상태 분석
10. 필요 종목 재검증 및 전체 재계산
11. HTML 레포트 생성·회귀검사
12. 등록 이메일로 전송하고 TASK·History에 결과 기록

> **중요:** AI가 키움 OpenAPI에서 직접 데이터를 수집한 것으로 간주하지 않습니다. 사용자 프로그램이 수집하고 사용자가 전달한 원본을 AI가 검증·분석합니다.

## 4. 기능군의 의미

### A. 사용자 및 기본 설정

작업 주체와 최종 결과 수신자를 확정하고, AI가 사용할 공식 원본의 파일 ID·버전·역할을 연결합니다. 사용자 필요 시 등록·변경하는 기능이며, 존재하지 않는 사용자용 알림·스케줄 설정을 구현 기능으로 주장하지 않습니다.

### B. 종목 마스터 관리

사용자가 1차 선택한 후보를 AI가 재무와 거래 위험, 가격 구조 관점에서 재검토합니다. AI가 등록 가능 여부와 등급을 제안하고 사용자가 승인한 뒤 시스템에 반영합니다. 부적합 종목은 사유와 함께 제외합니다.

### C. 보유종목 관리

실제 보유 상태를 일반 감시 대상과 분리합니다. 보유종목은 신규 도달·근접 후보에서 제외하고, 평단·수량·계좌 같은 정보는 공개 문서에서 차단합니다.

### D. 데이터 수집·전달

한국 정규시장과 NXT 마감 후 사용자 프로그램이 키움 OpenAPI로 일·월·년 자료와 종목 상태를 수집합니다. 누락·중복·기준일을 자체검사해 원본을 만들고 사용자가 AI에 전달합니다.

### E. 결과 요청 및 분석

사용자가 결과를 요청하면 AI가 실행 TASK를 만들고 전체 대상을 전수검사합니다. 필수 자료가 부족하면 이를 미도달이나 정상으로 바꾸지 않고 NG/HOLD 또는 확정 불가로 처리합니다.

### F. 특수 검증

CB·유증·관리·거래정지·상장변경, 재무 변화, 가격 구조 붕괴, 오래된 등급처럼 일반 실행만으로 처리하기 어려운 상황을 재검증합니다. Rule·Logic 변경 후에는 과거 결과를 재사용하지 않고 전체 재계산과 회귀검사를 수행합니다.

### G. 레포트 생성·전달

검증된 동일 결과 패키지로 HTML을 만들고 발송 전 수신자·제목·기준일·첨부·중복을 확인합니다. 사용자가 결과를 요청했을 때 등록 이메일로 전송하며 생성, 발송 요청, 발송, 수신 확인을 분리하여 기록합니다.

### H. 운영 통제·복구

Rule의 Development·Live·History, TASK의 정상·NG·HOLD·이어가기, Session Lock·Heartbeat, 백업·복구를 관리합니다. 답변하기 곤란하거나 사용자 판단이 필요한 사항은 임의 확정하지 않고 TASK에 HOLD로 등록해 협의합니다.

## 6. TAG 최적화 경험의 위치

Report TAG는 Live 기능이 아니라 **Development 진단 도구**였습니다. 여러 Logic이 섞인 레포트에 Logic별 TAG를 임시로 표시하여 문제가 발생한 Logic의 허점과 누락·우선순위 오류를 찾고 최적화했습니다.

계속 사용하고 싶었지만 다음 한계가 반복되었습니다.

- TAG가 출력 문맥과 처리 부담을 증가시킴
- 작은 변경에도 제거된 TAG나 이전 출력 형식이 복원됨
- 규칙을 보강해도 AI의 비결정적 재구성을 완전히 막지 못함
- TAG 자체가 Live 결과를 복잡하게 하고 사용자에게 불필요한 정보가 됨

따라서 Logic 보완·최적화와 회귀검사가 완료된 뒤 TAG를 제거했습니다. 이는 기능 실패를 숨긴 것이 아니라, 진단 목적을 달성한 임시 계측을 Live에서 걷어낸 개발 경험입니다. 자세한 내용은 [Retired Report TAG Optimization](../retired-report-tag-optimization.md)을 참조하십시오.
